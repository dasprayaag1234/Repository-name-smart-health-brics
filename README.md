# Smart Health & Supply Chain Resilience — Track 3

Build with AI 2026 hackathon submission. A national-scale health resource and
supply-chain command center: demand forecasting, stock-out risk, procurement
recommendations, redistribution, route optimization, emergency surge
simulation, resource monitoring, a Gemini-powered AI assistant, role-based
dashboards, and a BRICS federated-learning demo.

## Stack

- **Backend:** Django + Django REST Framework, Python
- **ML:** XGBoost (demand forecasting), pandas/NumPy for feature engineering
- **Optimization:** custom nearest-neighbor + 2-opt over haversine distances (see note on routing below)
- **Frontend:** Next.js (App Router) + TypeScript + Tailwind + Recharts + react-leaflet
- **Database:** PostgreSQL/Supabase in production, SQLite automatically as a zero-config local fallback
- **AI:** Google Gemini API, with a rule-based fallback so the assistant works with no API key

## Quick start

### Backend

```bash
cd backend
python3 -m venv venv && source venv/bin/activate   # or venv\Scripts\activate on Windows
pip install -r requirements.txt
python manage.py migrate
python manage.py generate_demo_data          # populates realistic demo data
python manage.py run_pipeline                # computes forecasts/risk/redistribution/routes
python manage.py runserver                   # http://localhost:8000/api/
```

Optional: copy `.env.example` to `.env` and set `DATABASE_URL` (Postgres/Supabase)
and/or `GEMINI_API_KEY`. Neither is required to run the app.

### Frontend

```bash
cd frontend
npm install
cp .env.local.example .env.local             # points at http://localhost:8000/api by default
npm run dev                                  # http://localhost:3000 -> redirects to /national
```

Dashboards: `/national`, `/supplier`, `/dealer`, `/facility`, `/brics`.

## Adding your real datasets

Drop CSVs into `backend/datasets/` following the structure in
`backend/datasets/dataset_config.json` (paths + required columns are all
documented there), then run:

```bash
python manage.py load_datasets    # imports whatever real CSVs are present; skips the rest
python manage.py run_pipeline     # recompute forecasts/risk/redistribution/routes from real data
```

Check `GET /api/dataset-status/` at any time to see exactly which datasets
are real vs. still running on demo data. Nothing needs to be "complete" —
partial real data (e.g. real facilities but demo inventory) works fine.

## What's real vs. labelled demo/abstraction

Per the brief, several pieces are intentionally simplified and **clearly
labelled as such in both the API and the UI** rather than pretending to be
something they're not:

- **Demand forecasting** uses a real XGBoost model with lag/rolling/calendar
  features when there's enough history; falls back to a weighted moving
  average when there isn't (`is_demo_fallback` in the API response).
- **Route optimization** uses great-circle distances and an assumed average
  road speed — there's no live traffic/routing API wired in. Every
  `OptimizedRoute` sets `is_demo_abstraction: true`.
- **BRICS federated learning** uses synthetic per-country metrics to
  demonstrate the local-model → aggregation → global-model concept. No real
  partner-country health data is used or required (`is_synthetic_demo: true`
  throughout, and the BRICS dashboard shows this disclaimer directly).
- **Demo data** (facilities, inventory, HMIS footfall, orders) generated by
  `generate_demo_data` is flagged `is_demo_data: true` on `Facility` rows
  and is fully replaced once you run `load_datasets` with real CSVs.

## Architecture

```
datasets/ (CSV) ──┐
                   ├─> data_loader.py (validates) ──> Django models (Postgres/SQLite)
generate_demo_data ┘
                          │
                          ▼
                 core/ml/forecasting.py (XGBoost demand forecast)
                          │
                          ▼
                 core/ml/risk.py (stock-out risk: Projected Stock = Current + Incoming − Forecast)
                          │
                          ▼
                 core/ml/redistribution.py (shortage <-> surplus matching)
                          │
                          ▼
                 core/ml/route_optimization.py (vehicle routing, demo abstraction)
                          │
                          ▼
                 core/pipeline.py (orchestrates + persists all of the above)
                          │
                          ▼
              REST API (core/views.py) <──> Next.js dashboards
                          │
                 core/ai/assistant.py (Gemini, grounded in the same DB numbers)
```

`core/ml/emergency_simulation.py` runs the same risk engine with demand
scaled up by a surge factor, as a what-if sandbox that doesn't touch the
live pipeline output.

## Key API endpoints

| Endpoint | Purpose |
|---|---|
| `GET /api/dashboard/national/` | KPIs, top risks, top redistribution recs, by-state breakdown |
| `GET /api/dashboard/brics/` | Federated learning rounds (synthetic demo) |
| `GET /api/dashboard/<supplier\|dealer\|facility>/` | Role-scoped views |
| `GET /api/forecast/?facility=&medicine=&horizon=` | Full XGBoost forecast for one pair |
| `GET /api/stock-risks/?risk_level=&state=` | Filterable risk list |
| `GET /api/redistribution/` | Source → destination → medicine → quantity → reason |
| `GET /api/routes/` | Optimized vehicle routes |
| `POST /api/pipeline/run/` | Recompute everything |
| `POST /api/emergency-simulation/` | `{surge_pct, scope_state}` → before/after |
| `POST /api/ai-assistant/` | `{question}` → Gemini or fallback answer |
| `GET /api/dataset-status/` | Real vs. demo status per dataset |

## Known limitations / next steps

- Redistribution "approve transfer" and shipment creation from the UI is
  not wired up yet — recommendations are read-only in the dashboard.
- No authentication/role gating — the 5 dashboards are all publicly
  reachable routes for demo purposes.
- Route optimization is the labelled great-circle abstraction described
  above, not a full OR-Tools VRP solve against a real road network.
- Emergency simulation samples up to 80 facilities per run to stay
  interactive rather than scoring the full national dataset live.
